# Deployment Documentation

This document describes how to **deploy**, **start**, **stop**, and **view logs** for the
Agent Studio web service. It fulfills the missing documentation requirement from the
review of ticket #9 (Deploy and install script).

## Prerequisites

* Ubuntu 22.04 (or later) VM with root access.
* Internet connectivity for downloading Docker packages.
* The repository must be cloned on the VM (the `deploy/` directory is part of the clone).

## Installation / Deploy

The entry‑point for a fresh install or a repair is the script
`deploy/install.sh`. It is **idempotent** – running it multiple times will not cause
duplicate installations or errors.

```bash
sudo ./deploy/install.sh
```

The script performs the following steps:

1. **Verify root** – exits if not run as root.
2. **Install Docker** if the `docker` command is not present.
3. **Enable the Docker daemon** if it is not already running.
4. **Install the Docker Compose CLI plugin** (bundled with Docker) or fall back to a manual binary.
5. **Pull the latest images** defined in `deploy/docker-compose.yml` and bring the services up.
6. **Health‑check** – makes an HTTPS request to the application until a `2xx` response
   is received (up to 30 seconds).
7. Prints a short summary and exits with status 0.

All actions are guarded with checks so that a second execution simply reports that the
components are already installed and then proceeds to the health‑check step.

## Starting / Stopping Services

The services are defined in `deploy/docker-compose.yml`. Use Docker Compose to control
them:

* **Start** (or restart after a reboot):
  ```bash
  sudo docker compose -f deploy/docker-compose.yml up -d
  ```

* **Stop**:
  ```bash
  sudo docker compose -f deploy/docker-compose.yml down
  ```

* **View logs** (follow live output):
  ```bash
  sudo docker compose -f deploy/docker-compose.yml logs -f
  ```

## Reboot Behaviour

Systemd unit files are installed by the `install.sh` script (inside the Docker
Compose setup) to automatically start the containers on VM reboot. After a reboot the
VM will run `docker compose -f deploy/docker-compose.yml up -d` automatically, so the
public URL becomes reachable again without manual intervention.

## Verification

* **Idempotency** – Running the script a second time prints messages such as
  "Docker already installed" and completes successfully.
* **Health check** – The script will block until the application returns HTTP 200 or
  abort after 30 seconds.

These behaviours are covered by automated tests in `tests/test_deploy_install.py`.
